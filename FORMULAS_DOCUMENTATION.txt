ECLAT (Equivalence Class Clustering and Bottom-up Lattice Traversal)
Purpose: Discover frequent itemsets and association rules from student profiles
Application: Find skill combinations that predict job types and employability levels

2.1 ECLAT - CORE FORMULAS
──────────────────────────

FORMULA 1: Support (for frequent itemsets)
─────────────────────────────────────────
    support(I) = |T_I| / n_total

Where:
    I = Itemset (e.g., {"skill:python", "skill:react"})
    T_I = Set of transaction IDs containing all items in I
    n_total = Total number of transactions
    |T_I| = Cardinality (count) of transaction set

Range: [0, 1] (0% to 100%)
Interpretation: Fraction of all students who have this itemset
Minimum Support Threshold: 0.02 (2% of all students)

Example:
    If 10 out of 500 students have skills "Python" AND "React"
    support("Python" ∩ "React") = 10 / 500 = 0.02 (2%)


FORMULA 2: Confidence (for association rules)
───────────────────────────────────────────────
    confidence(A → C) = support(A ∪ C) / support(A)
                      = P(Consequent | Antecedent)

Where:
    A = Antecedent (conditions: e.g., skills, certifications)
    C = Consequent (prediction: e.g., job type)
    support(A ∪ C) = Fraction with both A and C
    support(A) = Fraction with A

Range: [0, 1] (0% to 100%)
Interpretation: If student has A, what's probability they have C?
Minimum Confidence Threshold: 0.10 (10%)

Example:
    Rule: "Python Skills" → "Developer Track"
    If 80 students have Python AND are Developers
    If 100 students have Python (regardless of role)
    confidence = 80 / 100 = 0.80 (80% of Python students become developers)


FORMULA 3: Lift (strength/interestingness of rules)
──────────────────────────────────────────────────
    lift(A → C) = confidence(A → C) / support(C)
                = P(C | A) / P(C)
                = [support(A ∪ C) / support(A)] / [support(C) / n_total]

Where:
    confidence(A → C) = From Formula 2 above
    support(C) = Fraction of transactions containing C
    support(A ∪ C) / support(A) / support(C) = Normalized

Range: [0, ∞) (theoretically unbounded)
Interpretation:
    lift = 1: A and C are independent (no association)
    lift > 1: A and C are positively associated (rule is interesting)
    lift < 1: A and C are negatively associated (rare combination)

Example:
    Rule: "Web Development" → "Data Analyst Track"
    If support(Web Dev) = 0.30 (30% have this skill)
    If support(Data Analyst) = 0.20 (20% target this track)
    If support(Web Dev ∪ Data Analyst) = 0.08 (8% have both)
    
    confidence = 0.08 / 0.30 = 0.267 (26.7%)
    lift = 0.267 / 0.20 = 1.33
    
    Interpretation: Students with Web Dev are 1.33x more likely to want Data Analyst role

2.2 ECLAT - ALGORITHM PSEUDOCODE
─────────────────────────────────

function _eclat(prefix, prefix_tidset, items, min_support, max_itemset_size):
    for each item in items:
        next_tidset = intersection of prefix_tidset with item's transaction set
        support_count = size of next_tidset
        
        if support_count >= min_support:
            next_prefix = prefix + item
            ADD (next_prefix, support_count) to results
            
            if length(next_prefix) < max_itemset_size:
                suffix = find all items in items that can extend next_prefix
                if suffix not empty:
                    RECURSIVELY call _eclat with next_prefix

Time Complexity: O(n * 2^m) where n=transactions, m=items (exponential)
Space Complexity: O(m) for prefix tracking

2.3 ECLAT - IMPLEMENTATION IN PATHTOTECH
──────────────────────────────────────────

STEP 1: Build Transaction Set
──────────────────────────────
For each student row in dataset:
    - Extract skill tokens: skill:python, skill:react, etc.
    - Extract job type: job:developer, job:data_analyst, etc.
    - Extract employment level: level:high_employability, level:low_employability
    - Extract certifications: cert:has_cert or cert:no_cert
    - Add all tokens to a transaction (set of items)

Example Student Transaction:
    {"skill:python", "skill:react_js", "skill:nodejs", 
     "job:developer", 
     "level:high_employability",
     "cert:has_cert"}

STEP 2: Mine Frequent Itemsets
───────────────────────────────
Input Parameters:
    - min_support = 0.02 (2% of 500 = 10 students minimum)
    - max_itemset_size = 3 (find itemsets of size 1, 2, 3)
    - top_k = 20 (return top 20 rules)

Process:
    1. Count each item's transaction ID set
    2. Filter items appearing in ≥ 10 transactions
    3. Use ECLAT recursion to build larger itemsets
    4. Track support count for each itemset

STEP 3: Generate Association Rules
──────────────────────────────────
For each 2+ item itemset:
    For each possible consequent in itemset:
        antecedent = all other items
        
        Calculate:
            confidence = support(A ∪ C) / support(A)
            lift = confidence / support(C)
        
        If confidence ≥ 0.10 (min threshold):
            ADD rule to results

STEP 4: Cluster-Specific Rules (Optional)
──────────────────────────────────────────
Repeat ECLAT process for each GMM cluster separately:
    - Only use transactions from students in that cluster
    - Lower support threshold: 0.02 (2% of cluster size)
    - Extract rules specific to each cluster (5 clusters = 5 rule sets)

GMM (Gaussian Mixture Model)
Purpose: Cluster students into employability groups and determine individual scores
Application: Segment students into 5 tracks; predict employability level

3.1 GMM - CORE FORMULAS
───────────────────────

FORMULA 1: Gaussian Probability Density Function (PDF)
────────────────────────────────────────────────────────
    𝒩(x | μ_k, Σ_k) = 1 / √[(2π)^d |Σ_k|] × exp(-½(x - μ_k)^T Σ_k^(-1) (x - μ_k))

Where:
    x = Feature vector (14-dimensional student profile)
    μ_k = Mean vector of cluster k
    Σ_k = Covariance matrix of cluster k
    d = Number of dimensions (14)
    |Σ_k| = Determinant of covariance matrix
    ^T = Transpose operator

Interpretation: Probability that student profile x belongs to cluster k
Range: (0, 1) continuous

Example:
    Student: gwa_norm=0.3, survey_avg=0.7, tech_skills=0.5, ...
    Cluster 1 (High Employability): μ=[0.4, 0.8, 0.6, ...], high Σ
    Probability = 0.25 (25% likely to be in this cluster)


FORMULA 2: Mixture Probability
───────────────────────────────
    P(x) = Σ_k π_k × 𝒩(x | μ_k, Σ_k)

Where:
    π_k = Mixing coefficient (weight) for cluster k
    Σ π_k = 1.0 (weights sum to 1)
    K = Number of clusters (5)
    
    P(x) = π_1×𝒩(x|μ_1,Σ_1) + π_2×𝒩(x|μ_2,Σ_2) + ... + π_5×𝒩(x|μ_5,Σ_5)

Interpretation: Total probability student belongs to ANY cluster
Range: (0, 1] (must be ≤ 1)

Example:
    P(student x) = 0.1×N(x|C1) + 0.2×N(x|C2) + 0.3×N(x|C3) + 0.25×N(x|C4) + 0.15×N(x|C5)
                 = 0.1×0.3 + 0.2×0.1 + 0.3×0.5 + 0.25×0.05 + 0.15×0.0
                 = 0.03 + 0.02 + 0.15 + 0.0125 + 0
                 = 0.2125


FORMULA 3: Responsibility (Posterior Probability)
──────────────────────────────────────────────────
    r_k(x) = P(k | x) = π_k × 𝒩(x | μ_k, Σ_k) / P(x)

Where:
    r_k(x) = Responsibility of cluster k for data point x
    P(x) = Mixture probability (Formula 2)
    Range: (0, 1) per cluster, Σ_k r_k(x) = 1.0

Interpretation: After seeing data x, probability it's from cluster k
Used for: Soft clustering (probabilistic assignment)

Example:
    For student x and 5 clusters:
    r_1(x) = 0.35 (35% likely from cluster 1)
    r_2(x) = 0.25 (25% likely from cluster 2)
    r_3(x) = 0.20 (20% likely from cluster 3)
    r_4(x) = 0.15 (15% likely from cluster 4)
    r_5(x) = 0.05 (5% likely from cluster 5)
    Sum = 1.0 ✓


FORMULA 4: Log-Likelihood (GMM objective function)
────────────────────────────────────────────────────
    log L = Σ_n log(P(x_n))
          = Σ_n log(Σ_k π_k × 𝒩(x_n | μ_k, Σ_k))

Where:
    n = Student index
    N = Total number of students
    
Interpretation: How well GMM explains the training data
Goal: MAXIMIZE log-likelihood (minimize negative log-likelihood)
Range: Negative infinity to 0 (closer to 0 is better)

Example:
    If log L = -1,234.56, this indicates the model fit


FORMULA 5: AIC (Akaike Information Criterion) - Model Complexity Penalty
──────────────────────────────────────────────────────────────────────────
    AIC = -2 × log L + 2 × p

Where:
    log L = Log-likelihood (Formula 4)
    p = Number of parameters
    
    For GMM: p = K × (d + d×(d+1)/2 + 1) - 1
           = K clusters × (means + covariance + weight)
    
    With K=5, d=14: p ≈ 5 × (14 + 105 + 1) - 1 = 595 parameters

Interpretation: Balance between model fit and complexity
Goal: MINIMIZE AIC (prefer simpler models that fit well)
Usage: Used to select optimal number of clusters (K)

Example:
    K=3: AIC = 2,100 (underfitting)
    K=5: AIC = 1,850 (optimal)
    K=8: AIC = 1,920 (overfitting)
    Choose K=5


FORMULA 6: BIC (Bayesian Information Criterion) - Stronger Complexity Penalty
─────────────────────────────────────────────────────────────────────────────
    BIC = -2 × log L + p × ln(n)

Where:
    log L = Log-likelihood
    p = Number of parameters
    n = Number of training samples
    ln(n) = Natural log of sample size (penalty grows with data)

Interpretation: Like AIC but penalizes complexity more strongly
Goal: MINIMIZE BIC
Usage: Preferred over AIC for larger datasets; used in PathToTech

Example (n=500):
    K=3: BIC = 2,100 + 595×ln(500) = 2,100 + 595×6.21 = 4,796 (bad)
    K=5: BIC = 1,850 + 595×ln(500) = 1,850 + 3,695 = 5,545 (okay)
    K=7: BIC = 2,000 + 595×ln(500) = 5,695 (worse)


FORMULA 7: Silhouette Score (Cluster Quality)
──────────────────────────────────────────────
    s(x) = (b(x) - a(x)) / max(a(x), b(x))

Where:
    a(x) = Average distance from x to other points in its cluster
    b(x) = Minimum average distance from x to points in other clusters
    
    s(x) ∈ [-1, 1]
    -1 = Point is in wrong cluster
     0 = Point on cluster boundary
     1 = Point deep in cluster

Overall Silhouette Score = Mean of s(x) for all points

Interpretation: Higher silhouette = better separated, more cohesive clusters
Goal: MAXIMIZE silhouette score (range -1 to 1, higher is better)

Example:
    Cluster 1 (Tight, well-separated): silhouette = 0.72
    Cluster 2 (Loose, overlapping): silhouette = 0.31
    Cluster 3 (Tight, well-separated): silhouette = 0.68
    Overall average: 0.57 (Good clustering)


FORMULA 8: Cross-Validated Negative Log-Likelihood
────────────────────────────────────────────────────
    CV-NLL = -1/n_test × Σ log(P(x_test | GMM_trained))

Where:
    n_test = Number of test samples
    P(x_test | GMM) = Probability of test data given trained GMM
    
    Process:
    1. Split data into 5 folds (80% train, 20% test)
    2. Train GMM on each fold's training set
    3. Evaluate negative log-likelihood on test set
    4. Average NLL across all 5 folds
    
    Reported as: mean ± std

Interpretation: Generalization error (lower is better)
Goal: MINIMIZE CV-NLL; std should be small (consistent performance)

Example:
    Fold 1: NLL = 2.45
    Fold 2: NLL = 2.38
    Fold 3: NLL = 2.41
    Fold 4: NLL = 2.39
    Fold 5: NLL = 2.43
    
    Mean NLL = 2.412 ± 0.024
    Interpretation: Model generalizes well (low std)


FORMULA 9: Cluster Quality Score (for employability level assignment)
──────────────────────────────────────────────────────────────────────
    quality_k = 0.30 × gwa_norm + 0.25 × survey_avg + 0.20 × tech_skills_norm 
              + 0.15 × soft_skills_avg + 0.10 × cert_norm

Where:
    All values are normalized to [0, 1]
    gwa_norm = (5.0 - gwa) / 4.0 (inverse: lower GPA = higher score)
    survey_avg = mean of 9 survey categories (1-5 scale, divided by 5)

Weights:
    30% = Academic Performance (GPA/GWA)
    25% = Survey Competencies
    20% = Technical Skills
    15% = Soft Skills
    10% = Certifications
    ────
    100% Total

Interpretation: Weighted average indicating cluster's average employability
Range: [0, 1]
Used for: Assigning "Low", "Moderate", or "High" employability labels

Example:
    Cluster 1: quality = 0.30×0.6 + 0.25×0.7 + 0.20×0.4 + 0.15×0.8 + 0.10×0.3

    Cluster 2: quality = 0.30×0.2 + 0.25×0.3 + 0.20×0.1 + 0.15×0.2 + 0.10×0.1

    Cluster 3: quality = 0.30×0.9 + 0.25×0.85 + 0.20×0.8 + 0.15×0.9 + 0.10×0.7
             = 0.27 + 0.2125 + 0.16 + 0.135 + 0.07 = 0.8475

FORMULA 10: Cluster Weight (for ensemble predictions)
───────────────────────────────────────────────────────
    weight_k = shifted_quality_k / Σ shifted_qualities

Where:
    shifted_quality_k = quality_k - min_quality + 1e-6
    (Ensures all weights positive)
    
    Σ weight_k = 1.0 (weights sum to 1)

Interpretation: Relative importance of each cluster in final prediction
Used for: Weighted ensemble when combining cluster predictions

Example (5 clusters, shifted qualities):
    Cluster 1: shifted = 0.585 - 0.195 + 0.000001 = 0.390
    Cluster 2: shifted = 0.195 - 0.195 + 0.000001 = 0.000001
    Cluster 3: shifted = 0.8475 - 0.195 + 0.000001 = 0.653
    Cluster 4: shifted = 0.421 - 0.195 + 0.000001 = 0.226
    Cluster 5: shifted = 0.310 - 0.195 + 0.000001 = 0.115
    
    Sum = 1.384
    
    Weights:
    w1 = 0.390 / 1.384 = 0.282 (28.2%)
    w2 = 0.000001 / 1.384 ≈ 0.0% (essentially zero)
    w3 = 0.653 / 1.384 = 0.472 (47.2%)
    w4 = 0.226 / 1.384 = 0.163 (16.3%)
    w5 = 0.115 / 1.384 = 0.083 (8.3%)
    Sum = 1.0 ✓

3.2 GMM - EXPECTATION-MAXIMIZATION ALGORITHM
──────────────────────────────────────────────

EM Algorithm Overview (iterations to converge):

STEP 1: Initialize (Iteration 0)
    - Start with K=5 clusters
    - Initialize μ_k as random data points (or k-means initialization)
    - Initialize Σ_k as identity matrices
    - Initialize π_k = 1/K = 0.2 (uniform weights)

STEP 2: E-Step (Expectation)
    For each training sample x_n:
        For each cluster k:
            Calculate r_k(x_n) = π_k × 𝒩(x_n | μ_k, Σ_k) / P(x_n)
            (Update responsibility of each cluster for this point)
    
    Calculate log-likelihood = Σ_n log(P(x_n))

STEP 3: M-Step (Maximization)
    For each cluster k:
        Calculate new parameters based on responsibilities:
        
        N_k = Σ_n r_k(x_n)  (effective number of points in cluster)
        
        μ_k_new = (1/N_k) × Σ_n r_k(x_n) × x_n
        (Weighted mean: points with high responsibility contribute more)
        
        Σ_k_new = (1/N_k) × Σ_n r_k(x_n) × (x_n - μ_k_new)(x_n - μ_k_new)^T
        (Weighted covariance)
        
        π_k_new = N_k / N
        (New weight: fraction of points assigned to cluster)

STEP 4: Check Convergence
    If |log-likelihood_new - log-likelihood_old| < tolerance:
        CONVERGED ✓
    Else:
        Go to STEP 2 (repeat until convergence)

PathToTech Settings:
    - Max Iterations: 300
    - Tolerance: 1e-3 (default scikit-learn)
    - Multiple Initializations: 5 (try 5 different random starts, pick best)
    - Covariance Type: "full" (full covariance matrices, not diagonal)

Typical Convergence:
    Most convergence happens in 10-50 iterations
    Final ~200 iterations have minimal log-likelihood change


3.3 GMM - MODEL SELECTION PROCESS
──────────────────────────────────

Testing Range: K = 2 to 8 clusters

For each K value:
    1. Fit GMM with K components
    2. Calculate AIC = -2*log_L + 2*p
    3. Calculate BIC = -2*log_L + p*ln(n)
    4. Check if converged
    5. Record iteration count

Comparison Table Example (n=500):
────────────────────────────────
K  | Log-L    | AIC    | BIC    | Converged | Iterations
─────────────────────────────────────────────────────────
2  | -1,800   | 3,700  | 3,850  | Yes       | 45
3  | -1,200   | 2,500  | 2,700  | Yes       | 62
4  | -950     | 2,050  | 2,300  | Yes       | 78
5  | -900     | 1,950  | 2,250  | Yes       | 91   ← SELECTED (lowest BIC)
6  | -890     | 1,980  | 2,340  | Yes       | 105
7  | -885     | 2,020  | 2,440  | Yes       | 112
8  | -883     | 2,080  | 2,560  | Yes       | 128

SELECTION LOGIC:
    1. Find minimum BIC value (K=5: BIC=2,250)
    2. If BIC values tied: use AIC as tiebreaker
    3. Prefer K that balances fit vs. complexity
    4. Verify convergence (all should be True)
    5. Final choice: K=5 clusters

3.4 GMM - IMPLEMENTATION IN PATHTOTECH
───────────────────────────────────────

STEP 1: Feature Normalization
──────────────────────────────
Input: Raw 14-dimensional features (different scales)
    - gwa_norm: [0, 1]
    - survey_avg: [0, 1]
    - tech_skills_norm: [0, 1]
    - etc.

StandardScaler (Zero-mean, Unit Variance):
    x_scaled = (x - mean) / std_dev
    
    For each feature:
        Calculate mean and std from training data
        Apply transformation to all samples
        Result: Mean ≈ 0, Std ≈ 1

Example:
    Feature: gwa_norm
    Raw values: [0.1, 0.3, 0.5, 0.4, 0.6, ...]
    Mean: 0.38, Std: 0.18
    
    Scaled:
    0.1 → (0.1 - 0.38) / 0.18 = -1.56
    0.3 → (0.3 - 0.38) / 0.18 = -0.44
    0.5 → (0.5 - 0.38) / 0.18 = 0.67
    0.4 → (0.4 - 0.38) / 0.18 = 0.11
    0.6 → (0.6 - 0.38) / 0.18 = 1.22

STEP 2: Fit GMM
───────────────
Use EM algorithm (see section 3.2) to train model:
    - Input: 500 students × 14 features (scaled)
    - Process: ~100 iterations of E-step and M-step
    - Output: 5 cluster centers (μ_k), covariances (Σ_k), weights (π_k)

STEP 3: Predict Cluster Assignment
──────────────────────────────────
For each student:
    Calculate responsibility r_k(x) for each cluster k
    Assign to cluster with highest responsibility
    
    cluster_id = arg_max_k r_k(x)

Example:
    Student responsibilities: [0.02, 0.08, 0.65, 0.20, 0.05]
    Assigned to cluster: 3 (65% probability)

STEP 4: Get Probability Estimates
──────────────────────────────────
For predictions on new students:
    responsibilities = gmm.predict_proba(x_scaled)
    
    Returns 5-column array with probabilities per cluster
    Example: [0.05, 0.10, 0.72, 0.08, 0.05]

STEP 5: Derive Employability Level
────────────────────────────────────
1. Calculate quality score for each cluster (Formula 9)
2. Rank clusters by quality
3. Assign labels:
    - Bottom 33%: "Low Employability"
    - Middle 33%: "Moderate Employability"
    - Top 33%: "High Employability"

Example (5 clusters):
    Quality scores: [0.32, 0.51, 0.18, 0.65, 0.42]
    Sorted: [0.18, 0.32, 0.42, 0.51, 0.65]
    
    Percentile ranges:
    0-33%:  0.18, 0.32 → Clusters for "Low"
    33-66%: 0.42      → Cluster for "Moderate"
    66-100%: 0.51, 0.65 → Clusters for "High"

3.5 GMM - USAGE IN RECOMMENDATIONS
────────────────────────────────────

For a new student with profile x:

Step 1: Normalize features
    x_scaled = (x - training_mean) / training_std

Step 2: Get cluster assignment probabilities
    prob = gmm.predict_proba([x_scaled])[0]
    Example: [0.05, 0.25, 0.50, 0.15, 0.05]

Step 3: Get primary cluster
    cluster_id = arg_max(prob) = 2
    probability = prob[2] = 0.50 (50% confidence)

Step 4: Get employability level for that cluster
    If cluster_id = 2 and cluster_2_level = "Moderate Employability":
        Student's level = "Moderate Employability"

Step 5: Use level in filtering
    Filter ECLAT rules by this level:
    - Only return rules with antecedent containing "level:moderate_employability"
    - Rules like: "skill:python" → "Developer"
    - Skip rules like: "level:high_employability" → "Researcher"

Step 6: Rank job recommendations
    Combine:
    - Cluster assignments (hard constraint)
    - ECLAT rule confidences (soft ranking)
    - Cosine similarity to cluster center
    
    Final: Top 5 recommended job tracks

SECTION 7: KEY INSIGHTS AND INTERPRETATIONS
═════════════════════════════════════════════════════════════════════════════════

7.1 HOW GMM WORKS IN THIS SYSTEM
─────────────────────────────────

✓ GMM segments students into 5 career tracks (clusters)
✓ Provides soft probabilistic assignment (not hard clustering)
✓ Creates employability levels (Low/Moderate/High) per cluster
✓ Offers confidence levels for predictions

Strengths:
    - Probabilistic framework (uncertainty quantification)
    - Doesn't force hard assignment to one cluster
    - Captures overlapping career interests
    - Scalable to many students

Limitations:
    - Assumes Gaussian distribution (may not fit all data perfectly)
    - Requires numeric features only
    - Ignores skill combinations (that's what ECLAT does)


7.2 HOW ECLAT WORKS IN THIS SYSTEM
────────────────────────────────────

✓ ECLAT discovers skill combinations that predict employability
✓ Generates actionable rules: "If you have X skills, you're likely Y"
✓ Provides confidence (how reliable the rule is)
✓ Provides lift (how much better than random chance)

Strengths:
    - Finds interpretable patterns
    - Works with categorical data (skills, jobs, etc.)
    - Generates concrete recommendations
    - Fast for moderate-sized datasets

Limitations:
    - Doesn't consider numeric relationships directly
    - May find spurious associations in small clusters
    - Requires manual threshold tuning


7.3 WHY USE BOTH GMM + ECLAT
───────────────────────────

GMM provides:
    ✓ Dimensionality reduction (14 features → 1 cluster)
    ✓ Probabilistic framework
    ✓ Employability level classification

ECLAT provides:
    ✓ Interpretable rules
    ✓ Specific improvement suggestions
    ✓ Skill gap analysis

Combined approach:
    1. GMM determines WHERE student is (cluster, level)
    2. ECLAT determines HOW to improve (which skills matter)
    3. Results are filtered by GMM level (only relevant rules)


7.4 CRITICAL FORMULAS SUMMARY
──────────────────────────────

For Quick Reference:

Employability Score = 0.30×academic + 0.25×survey + 0.20×skills + 0.15×soft + 0.10×cert

Support(Rule) = Students with Rule / Total Students

Confidence(A→B) = Students with A∩B / Students with A

Lift(A→B) = Confidence(A→B) / Support(B)
          = How much more likely B when A occurs
          > 1: positive correlation
          = 1: independent
          < 1: negative correlation

Cluster Quality = 0.30×gpa + 0.25×survey + 0.20×skills + 0.15×soft + 0.10×cert
                (All normalized to [0,1])

Silhouette = (b-a) / max(a,b)
           = How well-clustered the data is
           [-1, 1], higher is better

BIC = -2×log_L + p×ln(n)
    = Model selection criterion
    Lower is better (balance fit vs complexity)
